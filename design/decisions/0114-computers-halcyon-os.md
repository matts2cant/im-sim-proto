# 114. Computers: Halcyon OS with Mail, Files and Security replace the security terminal

Status: Accepted (replaces the terminal of [ADR 0080](0080-credentials-terminal.md) and [ADR 0083](0083-security-terminal-redesign.md); implements the computers of [ADR 0112](0112-hacking-reconciled-with-the-built-game.md))

Date: 2026-11-11

## Context

ADR 0112 decided that computers running a simple desktop replace the M8 security terminal, that the terminal's Camera tab becomes a Security app listing only the devices a computer controls, and that a computer you have an account on can be used remotely from the deck ([mockup](../prototypes/hacking_screens.html)). M12a builds this in parallel with the network layer, tracers and the deck (another brief), against a small contract: `Computer.open_desktop(viewer, user, remote)`, `Computer.desktop_closed`, `Computer.of()` (this brief's) and `DeviceAccount` / `DeviceAccounts.try_login()` (the network brief's).

## Decision

- **Components, not a class of object.** A computer is a device entity with a `Computer` component (`objects/computer/computer.gd`), its `DeviceAccounts` (local accounts) and a `ComputerUse` (the `Usable`: E uses it bare-handed). `objects/computer/computer.tscn` is the old terminal's wall unit with these components; every terminal instance (the security wing's booth, now `BoothComputer`, the warehouse's `SecurityConsole` and its two office PCs, the security showcase's `Console`) became one, with its accounts and current credentials.
- **Mail and Files are data.** A `ComputerData` `.tres` per computer holds `ComputerDocument`s: a mail (sender, subject, text, the account whose inbox holds it or every account's) or a file (name, text). Each can carry codes and logins (`codes`, `code_labels`, like a datapad) or be an **implicit clue** (a flag): nothing is learned, it is a note. Reading one (selecting it in the list; the first item is selected when the app opens) adds it to the reader's PersonalLog with source "Mail" or "Files" through `PersonalLog.add()` (the Journal and the HUD's "Added to log", not the reading overlay).
- **Logins.** `Computer.log_in()` goes through `DeviceAccounts.try_login(user, password, by)` (the network layer reports failures to tracers). The login screen's "Fill in" lists every login the PersonalLog knows under the computer's `credentials_id`, one per user, the latest learned for that user (`PersonalLog.code_entries()`, new). The Journal's Codes and logins lists one row per user for such a code id too. A wrong login shows "Wrong user or password." and beeps, but emits **no noise stimulus**: hacking is silent (hacking.md); the terminal's beep was noise 4.
- **Sessions.** A bare-handed login opens the computer's session (`session_user`, saved; a level can start a computer unlocked); Log out ends it. `open_desktop(viewer, user, false)` opens that session too. A remote desktop (`remote = true`) never opens or changes the local session.
- **The overlay** (`ComputerScreen`, a child of the Player like the HUD): an 85 % panel over the dimmed running world, like the Tab interface; the player's input is off, the mouse free, the HUD hidden; Esc or ✕ leaves (Esc never also opens the game menu), E never does; it closes when the user cannot act (dead, knocked out) or the computer dies, and a bare-handed session also when the user is more than 3 m away. Title bar: "Halcyon OS", host name and address, account and access level ("user" or "admin" from the account), a trace bar slot (`trace_bars()`, `add_trace_bar()`, `clear_trace_bars()`, the `opened(computer, remote)` signal: the network layer fills it), ✕. Login card, then a desktop with a dock (Mail, Files, Security, the account, Log out).
- **The address is a property.** The title bar and the Security app's detail pane show the address any component of the entity offers through `device_address() -> String` (the network layer's), like `DeviceStatus`; without one no address is shown.
- **Security app.** `Computer.devices()` lists the devices of the computer's cabled network (reached, or cut off and shown offline) that it **controls** (`Computer.controls()`, the one filter the network integration extends with "and the device trusts this computer"; until then every device on its network) and that have a **kind**: `ComputerConfig.kinds` maps an entity tag (`object.camera`, `object.turret`, `object.door`, `object.alarm_controller`, `object.siren`, `object.radio_base_station`, `object.panic_button`, `object.laser`) to a name, a group and an icon. Groups in `ComputerConfig.groups` order: Cameras and turrets, Doors, Alarm, Laser arrays. Switches and computers have no kind and are not listed. Icons are line drawings as data per kind (`DeviceIcon` strokes: polylines, rect, circle, arc, dash on a 24 px grid). The detail pane: name, kind and status, the live view for a device that has one (`DeviceStatus.has_view()`, today's camera feed: rendered only while shown), status words, address, one button per command it accepts from the config's label table (`danger_commands` red on hover), and the result line. A computer that controls none says so and points to the deck.
- **Remote desktops.** `open_desktop(viewer, user, true)` shows the same desktop on a layer above the deck (`REMOTE_LAYER` 26), in the deck's content area (`remote_area`, anchors; default the mockup's: right of a 150 px tools column, below a 45 px bar; the deck may set its own with `set_remote_area()`), with "Remote desktop · Halcyon OS · host · address" in its bar and "Back to the map". Back to the map or Esc closes it and emits `desktop_closed`; walking away does not (the deck's tether does), death does.
- **The terminal is gone.** `Terminal`'s usable, login and screen, `TerminalCredentials` (now `LoginCredentials`), `TerminalScreen` and its Camera and Network tabs are removed. The old network map's three files (`ui/terminal/network_graph.gd`, `network_layout.gd`, `network_view.gd`) belong to the deck brief and were not touched; so that they and their tests still compile until the deck replaces them, a stripped `Terminal` (only its row list of the cabled network and `cables()`, no scene uses it), `TerminalConfig` with `terminal.tres` and `TerminalStyle` stay, marked LEGACY, to be deleted when the deck's Map no longer needs them. The level tests' map readability checks build those rows on the computers' entities (`network_map_checks.gd` `rows_from()`).

## Alternatives considered

- **`Computer` as the `Usable` itself**: one node fewer, but the contract types it as a plain `Node`; a separate `ComputerUse` keeps the component usable by the deck without the E prompt.
- **One code id per account** (`warehouse_office_pc2.kbrandt`): Fill in would need the computer to know every account's code id; one code id per computer with "user:password" values keeps the datapads as they are.
- **Reading a mail through `PersonalLog.read()`**: opens the reading overlay over the computer.
- **Listing only the reachable devices** (hiding cut-off ones): the old terminal showed them offline, which tells the player their cut worked; kept.
- **Removing the map's dependencies outright**: the map files are the deck brief's; deleting `Terminal.Row` would break them and their tests until that brief lands.
