# Code audit, 2026-11-13

Two read-only audits after M14 (the user asked for a pause on features): systemic design (S#) and code quality / architecture (Q#). Fixes run in waves of non-overlapping agents; each finding's line numbers are as of master a404e4b and may have moved. Status is kept here as the waves land.

Overall: `core/` is content-free, the stimulus / receptron / effect pipeline is data-driven, no gameplay code branches on names or scene paths to decide behaviour, guards are data-only. The debt is horizontal (the same plumbing re-implemented per feature) plus a few structural risks below.

## Systemic design

- **S1 (high)** The EventLog (a 2000-entry debug ring buffer) is the gameplay event bus: objectives, the mission tally, kill/KO hit markers and network feedback parse entries and attribute actions by comparing node names (`player_names`, `shooter_names`, `entity.name == device_name`); the spawned player is renamed "Player" to fit. `levels/mission/mission_kit/mission.gd:249-250,281,342-352,378`, `mission_tally.gd:41-62`, `objectives/pick_up_objective.gd:11-17`, `ui/hud/network_feedback.gd:44-49,91-95`, `ui/hud/hit_marker.gd:64`. Fix: typed event kinds shared by emitters and consumers, entries carrying entity references (or a stable id), attribution by tag (`actor.player`), never by name. Status: done (fix-events, ADR 0136): entries keep their entities (`EventLogEntry.entity()`, `source_entity()`, `target_entity()`, Node data values such as `device.command`'s `by`); MissionTally, PickUpObjective and NetworkFeedback decide "the player" by the `actor.player` tag (`MissionData.player_tag`), HitMarkerRules watches the HUD's character by reference; broken and lit objects are keyed by node path; `player_names` / `shooter_names` / `_device_named` are gone and the spawned player is not renamed. Consumers listen to `entry_added` (none scanned the buffer; the rule is now written down in architecture.md).
- **S2 (high)** Network identity is a node name: firewall rules match `entity.name == value`; accounts, exploits, traces and Wi-Fi keys are keyed by the user's node name (`router_rule.gd:78-83`, `network_source.gd:58-59 user_key`, `device_accounts.gd:90-131`, `tracer.gd:135-189`, `access_point.gd:76-82`, `device.gd:339-347,400`, `exploit_items.gd:82`). Fix: rules match `Device.address`; users keyed by a stable exported id on a component (saveable). **Done** (fix-network-identity, ADR 0140): users are keyed by a `NetworkIdentity` (`objects/network/network_identity.gd`: a saved random id, or a fixed `id` set in a level), added from its scene on a character's first network act (`ensure()`; reads use `key_of()` and never add one) and recreated by a level snapshot as a spawned node; DeviceAccounts, DeviceIntrusion, Tracer/TraceModel and AccessPoint key by it and migrate saves keyed by node name (`user_keys` marker; the key goes to the character of that name). Firewall rules match `Device.address` only; the Firewall tool offers devices with an address. Logs keep node names. Level data needed no change (the warehouse rules already named addresses; the lab and wing have none); the lab tests' rules use addresses. `network_identity_test` covers two characters named alike, a renamed user, a renamed device's rule, a snapshot round trip and the migration.
- **S3 (high)** World systems read `PlayerInventory` (typed to `Player`): a guard with a keycard item cannot open a reader, only the player can disarm mines or use exploits (`keycard_lock.gd:27-40`, `exploit_items.gd:25,81`, `mine_disarm.gd:57-60`, `deck_session.gd:521`, `wireless_tool.gd:289`, `mission.gd:381-385` re-implements `PlayerInventory.of()`). Fix: a character-agnostic carried-items component; the player keeps its belt/hand UI layer on top. **Done** (wave 3, fix-inventory, ADR 0139): an `Inventory` component any character carries items in (`Inventory.of(entity)`, `items/inventory/inventory.gd`; the pure grid is `InventoryGrid`); `keycard_lock.gd` (`key_ids()`), `mine_disarm.gd`, `mission.gd` and `item_details.gd` read it; the player's `PlayerInventory` extends it with the belt and hand. `exploit_items.gd`, `deck_session.gd` and `wireless_tool.gd` were fix-network-identity's files this wave and still call `PlayerInventory` (a PlayerInventory is an Inventory: they switch to `Inventory.of()` next). Tests on minimal characters: a keycard opens a reader, a mine is disarmed into an Inventory.
- **S4 (medium)** The training dummy's script holds behaviour: its tipping duplicates `DownedPose`, and floating damage numbers no other entity can use (`actors/dummy/training_dummy.gd`). Fix: `DownedPose` + a new `DamageNumbers` component; the script shrinks to the reset hook. **Done** (wave 1): the dummy has `DownedPose` (so a lying dummy leaves the character layers like a guard's body) and a new `DamageNumbers` component (`actors/common/body/`, tuning `damage_numbers.tres`, tested on a minimal character); `training_dummy.gd` keeps `body`/`hitboxes` and the reset hook (a `restore` CONTACT).
- **S5 (medium)** "Down" has two sources of truth: `BodyParts.dead/unconscious` flags and the `state.dead/state.unconscious` tags; flag readers ignore a tag-only knockout (`body_parts.gd:40,76-81,148-150`, readers `training_dummy.gd:80`, `body_reset_button.gd:44`, `heal_effect.gd:18`, `health_tab.gd:205`). Fix: readers use `ActorState`, or the flags derive from the tags. **Done** (wave 1): the flags derive from the tags: `BodyParts.dead/unconscious` are gone, `is_dead()` / `is_unconscious()` read `state.*` (a container of its own without Tags); `down_state_test.gd` and `health_tab_test.gd` cover a tag-only knockout or death for every former reader.
- **S6 (medium, deferred to M15 Factions)** Sides are kind tags: friendly = `actor.guard`, hostile = `actor.player` in perception, lasers and turrets. Fix in M15: faction tags.
- **S7 (medium)** "Who is the player" three ways: the `actor.player` tag, the `player` group, node names; literals repeated (`perception_config.gd:9`, `mission_data.gd:16`, `extraction_zone.gd:13`, `level_exit.gd:10`, `player.gd:35,131`, `light_level_readout.gd:6`, `awareness_toggles.gd:51`, `spawn_tab.gd:175`). Fix: one constant, lookups through the tag; the group only as a debug index defined once. **Done** (wave 3, ADR 0139): `ActorState.PLAYER` is the one tag constant (perception, mission data and tally, extraction zone, level exit and turret presets default to it); the `player` group is `DebugPanel.PLAYER_GROUP`, read only through `DebugPanel.player()` (Spawn tab, alarm buttons, light readout); `Player.GROUP`, the light readout's constant and the alarm buttons' literal are gone.
- **S8 (medium)** Guard awareness queries the jamming field's static registry (one system calling another); the field is indexed twice (static `_active` and a group) (`awareness_effect.gd:55-57`, `jamming_field.gd:16,29-54`, `DeviceNetwork.is_jammed`). Fix: the field puts a `state.jammed` tag on entities inside it (or emits a uniform `jam` stimulus); radio receptrons and the network read the tag. **Done** (wave 2, ADR 0138): the field adds and removes `state.jammed` (`ActorState.JAMMED`) on entities with Tags it covers (every tick, unless another field covers them); `AwarenessEffect.radio`, `DeviceNetwork.is_jammed()` and `DeckSession.jammed()` read the tag; the group is the only index (static list gone).
- **S9 (medium)** Materials described three ways: `surface` metadata (constant defined three times), `material.*` tags (only shot FX falls back to them), `MaterialProfile`; footsteps on a metal-tagged crate use the default surface (`surface_table.gd:7`, `shot_fx_config.gd:16-18,53-66`, `kit_part.gd:11-14`, `movement_noise.gd`). Fix: one `Surface.of(collider)` (metadata for static geometry, else the material tag) used by footsteps, shot FX and impacts. **Done** (wave 2, ADR 0138): `objects/materials/surface.gd` (`Surface.META` / `WALL_META` defined once); `SurfaceTable.surface_of()` and `ShotFxConfig.group_for()` use it (its `tags` table folded into `surfaces`); the footstep probe also sees the objects layer, so a metal crate sounds and sparks as metal. `MaterialProfile` stays the object's own impact and break data.
- **S10 (medium)** UI restates rules: the health tab recomputes injury effects separately from `BodyParts`; "Cloaked: guards cannot see you" restates a per-perceiver rule (`health_tab_rules.gd:10-45`, `health_tab.gd:22-24`). - **S13 (low)** Feel constants in code: `awareness_behaviour.gd:16` SWEEP_PERIOD, `combat_behaviour.gd:34` STILL_SPEED, `weapon_holder.gd:370,688` volumes, `breakable.gd:146` unit_size.
